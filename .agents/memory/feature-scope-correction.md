用户 2026-11-06 明确纠正了两点：

1. 不要因为代码审查里出现“watermark 只支持 ASCII”这类**实现限制**，就自动把它升级成产品需求（CJK 水印、字体依赖评估）。用户从未要求中文水印。
2. 无论如何不要用“内置字体/打包字体”解决文字渲染；字体应来自系统（字体列表 API + 系统字体加载），没有字体就明确报错。

**Evidence:** 用户原话“我都听不懂你在说什么功能？我们哪有这个功能？”、“无论如何首先排除内置字体这种蠢方法”；图片工具重构（现名 `local.media.image.*`）与 `.agents/memory/image-tools.md`。

**Why:** 把审查观察当成需求会制造无人需要的依赖、体积和待办，并浪费多轮实现；内置字体会把部署问题变成仓库资产问题。

**How to apply:** TODO/计划里只写用户确认过的需求；对“代码目前不支持 X”先问这是限制还是需求。涉及字体时默认系统字体，禁止把字体文件加入仓库。若用户纠正了范围，立即从 TODO 撤回相关项，并记录到本记忆。
